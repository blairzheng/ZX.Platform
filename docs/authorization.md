# 角色与权限

[文档导航](README.md) · [接口契约](api.md#角色与权限接口) · [登录与会话](authentication.md)

采用“用户 → 多个角色 → 多个功能权限”。用户的有效权限为所有启用、未删除角色的权限并集，不提供用户直接授权或拒绝规则。JWT 仅保存身份与会话，不写入角色权限，因此改权无需重新签发 JWT。

## 权限目录

`Application/Authorization/IdentityPermissions.cs` 是当前服务的权限定义来源。Controller 使用对应常量，例如 `[Authorize(Policy = IdentityPermissions.UserRead)]`；新增权限时同时添加常量、中英文 `AccessMessages` 词条、接口 Policy 和前端权限入口。

启动时 `AuthorizationInitializer` 将常量同步到权限表：新增代码插入，已移除代码标记为不活跃。授权查询只承认当前代码声明的权限；旧角色关联保留但不再生效。权限管理页读取当前目录，无需人工插入权限记录。删除功能时也要删除相应权限声明；这里不自动扫描 Controller 来推断未使用的常量。

当前提供用户、SBU、角色、菜单四组权限；具体代码及对应接口集中在[接口契约](api.md)。功能权限不等于SBU数据范围，`UserSbu` 仍只是归属关系。

需要按 SBU 处理的 Identity 业务接口同时标注功能权限和 `[RequireSbu]`，例如 `[Authorize(Policy = "业务权限代码")]` 与 `[RequireSbu]`。后者要求 `X-SBU-ID` 为单个有效 GUID，并查询当前用户与未删除、已启用 SBU 的实时关联；缺失或格式错误返回 `400 / 600001`，无关联或 SBU 停用返回 `403 / 600005`。管理员也须明确关联 SBU，不因角色获得全部数据范围。Controller 注入 API 层的 `CurrentSbuContext`，将已校验的 `SbuId` 和服务端读取的 `SbuCode` 作为参数传给 Application Service；业务查询、详情和写操作仍须校验记录归属。没有 SBU 范围的全局接口不标注该特性，也不读取此上下文。其他业务服务须实现自己的同等服务端校验，不能依赖前端请求头或网关替代授权。

## 首个管理员

Identity 不提供公开注册，也不在启动时创建用户或管理员。全新数据库完成建表后，由数据库管理员或部署人员使用本地保存、未纳入代码管理的一次性 SQL，在同一事务中创建首个用户、内置 `ADMINISTRATOR` 角色及其用户关联。密码字段必须写入项目兼容的 BCrypt 哈希，不写明文。

运行 SQL 前停止 Identity，并确认 SQL 使用目标表 owner。脚本应在管理员角色或指定账号已存在时停止，避免重复创建；成功后再启动 Identity。应用启动仍会自动同步代码权限目录和默认菜单，管理员角色据此获得内置管理员的全部权限。服务器启动配置、User Secrets 和发布流水线都不再承担首个管理员创建。

本机当前使用的 SQL 保存在 MOM_Progress 工作目录的 `local-admin-init.sql`，不属于 ZX.Platform 仓库；该副本中的 schema 名称按本机环境设置。其他环境应由 DBA 按目标 schema 检查并执行相应 SQL。数据库结构初始化、清空与迁移见[数据库初始化与重建](database-initialization.md)。

后续用户和角色通过后台管理。数据库已存在管理员时，不要再次执行首次初始化 SQL；丢失管理员访问时，按 DBA 变更流程核实并修复用户、内置角色及关联。

内置管理员拥有当前服务全部声明权限，新增权限自动包含。内置角色不允许修改、禁用、删除或手动调整权限。只有内置管理员能授予或移除他人的内置管理员角色，且不能移除自己的该角色。用户不能禁用、删除自己；停用或删除其他内置管理员也要求操作者为内置管理员。这些校验不使用分布式锁，不承诺并发管理员互相撤权场景下的强一致。

## Redis 权限缓存

认证先验证 JWT 并核对 Redis 当前会话。需要功能权限的请求再使用一次 `MGET`，同时读取全局权限版本与该用户的权限快照；缺失或版本不一致时才查数据库，结果缓存 5 分钟。当前请求内复用结果，不建立跨请求本机 L1，也不通过 HTTP 调用 Identity 验权。`Auth/me` 同样读取权限快照。

缓存键位于当前 `AuthenticationRedis:KeyPrefix` 下：

- `authorization:{permissions}:version`：全局递增版本，不设置 TTL。
- `authorization:{permissions}:user:<userId>`：带版本的用户权限快照，TTL 为 5 分钟。

键使用相同 Redis hash tag，保证 `MGET` 的键处于同一槽。角色权限、角色状态、角色删除、用户角色、用户启停用及删除/恢复后，使全局版本递增。快照使用数据库查询开始前读到的版本，旧查询即使晚回填，也不能匹配新版本。当前规模先用全局版本简化依赖关系；一次改权会使其他用户也在下次访问重新加载权限。

数据库保存和 Redis 失效不是同一个事务。保存结果不确定也会在 `finally` 尝试失效，且不使用客户端取消令牌。Redis 故障返回 `503 / 600503`，不降级成本机缓存或放行；此时数据库变更可能已提交，恢复依赖后应查询实际状态并重新保存。已通过授权的请求不会被中途取消，接受读缓存与改权之间的小并发窗口。直接修改数据库不触发失效；若发生这种运维操作，需通过接口重新保存或重启服务同步目录并推进版本。

所有实例应部署一致的权限目录代码并使用相同数据库、Redis 与前缀。包含权限删除的版本切换要统一协调，旧实例启动可能重新激活其旧目录；不能据此承诺任意新旧版本混跑。

## 前端接入与边界

`Auth/me` 返回角色编码、权限代码、`isAdministrator` 和当前用户的菜单树 `menus`。前端用菜单树生成导航及业务路由，用权限控制按钮；服务端 Policy 独立执行，隐藏按钮不能替代授权。角色页可新增、修改、启停用、删除，按菜单树勾选操作权限；用户页可分配多个角色。将角色权限和用户角色分配权交给可信管理人员，这两项能够间接授予高权限。

管理员改权后，后端后续请求重新按缓存版本判断。其他浏览器没有权限推送，用户可点击头像菜单“刷新权限”或刷新浏览器更新菜单；当前浏览器修改授权后会主动读取 `Auth/me`。前端权限集合变化时清理标签及页面缓存，失权页面返回工作台。

当前仅提供 Identity 接口可复用的 SBU 请求校验特性，尚未接入具体的 SBU 业务接口，也不提供跨服务权限目录同步、在线用户列表或审计操作日志。其他服务仍需定义并执行自己的授权，不能直接把 Identity 的权限常量当成跨服务通用授权组件。

## 动态菜单与授权树

新增 `Menu` 表，与原有角色、权限、用户角色和角色权限四表配合；不增加 `RoleMenu`，角色授权仍只保存 `RolePermission.PermissionCode`。

- `directory`：组织目录，只能位于根或其他目录下，无路径、组件、权限。
- `page`：页面，只能位于根或目录下，关联一个查看权限、唯一路径、本地组件标识、菜单/标签显示和缓存设置，可固定标签。
- `action`：操作权限，必须挂在页面下，关联当前代码声明的权限，不生成导航或路由。

`Auth/me` 查询一次菜单表，排除停用节点及其后代、操作节点、没有查看权限的页面和空目录；内置管理员也不能看到已移除权限定义的页面。普通业务请求不查询菜单表，沿用 Redis 权限校验。其他浏览器需要“刷新权限”或刷新页面才能更新导航；当前浏览器维护菜单后自动刷新。菜单元数据变化同样使前端重建路由、标签和页面缓存。`ShowInMenu=false` 仅隐藏导航，页面仍返回并注册路由；隐藏目录会隐藏其下级入口，前端去掉过滤后的空目录。`ShowInTags=false` 不产生标签或缓存，`Affix=true` 的页面初始化为不可关闭的固定标签。显示字段不改变角色授权。

`Roles/permissionTree` 用菜单组织操作叶子；若页面未挂自己的查看权限，临时补一个“查看页面”叶子。没有挂到菜单下的有效权限放入“未归类权限”，移除代码定义的操作不再参与授权。页面和目录是分组，保存时只提交勾选叶子的权限代码；操作授权不自动附带查看权限。停用菜单仅隐藏入口，不撤销 API 权限；撤权必须修改角色授权。

启动通过 `DefaultMenus` 仅补齐缺失的系统、用户、SBU、角色、菜单及操作节点，不覆盖管理员维护的标题、图标和排序。内置节点不允许改结构、停用或删除，保留管理入口；自定义节点允许维护，删除前须先移除下级。菜单编码删除后保留，页面路径和操作权限在未删除的对应类型中唯一。层级变更拒绝循环及过深祖先；这些预查询不是跨请求锁，接受与现有安全变更相同的小并发窗口。

页面组件目前限定为 `SystemUser`、`SystemSbu`、`SystemRole`、`SystemMenu`，前端通过本地显式映射懒加载。新增业务页面需同时登记后端组件白名单、权限定义和前端组件映射，再在菜单管理中配置入口；后台不执行数据库提供的任意文件路径。菜单提供中文/英文标题，英文为空时回退中文。
