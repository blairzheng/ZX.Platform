# SBU / MES 与低代码并行实施交接

更新于 2026-10-29。两条工作线可以并行推进；低代码接入 MES 数据集时，复用 SBU / MES 工作线验证过的接口与数据范围规则。

## 当前状态与共同契约

- Identity 已支持一个用户关联多个 SBU。`Auth/me.sbus` 只返回该用户关联、未删除且启用的 SBU，按编码排序。前端默认选第一个，允许在用户名后切换；无 SBU 的用户仍可使用全局功能。
- 前端按 SBU 的请求显式设置 `sbuScoped: true`，统一请求层发送 `X-SBU-ID`。全局接口不发送这个头；切换 SBU 后旧请求响应会被丢弃。
- Identity API 已有 `[RequireSbu]`，负责检查请求所选 SBU 是否存在、启用且属于当前用户，并在 API 层的 `CurrentSbuContext` 中提供服务端读取的 `SbuId` 和 `SbuCode`；Controller 将这两个值传给 Application Service。业务功能仍需独立的 `[Authorize(Policy = ...)]`，并在查询、详情、导出和写入时用已验证的 SBU 过滤记录。其他业务服务需要实现等价校验，不能只信任请求头、前端菜单或 Gateway。
- 现有后端已准备按别名打开外部 Oracle 连接的工厂，本机 `MesE`、`MesF`、`MesEB` 已完成连接验证，但尚未实现站点查询接口。第一阶段在现有后端内增加 MES 业务模块；下面的 E/F/EB 对照只属于站点查询规则，不是全局绑定规则。没有任何 MES 数据表由本平台的 EF Migration 管理。
- 当前没有低代码运行时或生成器。现有角色权限、动态菜单和页面组件白名单是低代码工作线要复用的边界。

## 工作线 A：SBU 与 MES 外部数据集

负责人继续维护 `ZX.Platform` 的 SBU 校验、现有后端中的 MES 业务模块，以及 `ZX.front.vue` 的站点查询页面和 API；不修改低代码配置和编辑器实现。外部连接配置与生命周期见[外部 Oracle 数据源](external-oracle-data-sources.md)。

1. **已完成：补齐已验证的请求上下文。** `[RequireSbu]` 从数据库一次读取用户关联且启用的 SBU，提供 ID 和服务端查到的 Code；不能从客户端传来的 Code 决定查询策略。功能权限仍单独校验。未配置 SBU 的功能保持全局行为。
2. **已完成：准备外部连接能力。** 现有后端按服务端别名配置外部 Oracle 连接，支持后续查询和写入；E/F/EB 各自使用独立连接池，不与 Identity 数据库连接混用。本机三个连接均已打开验证并释放。查询和写入的命令超时、事务及分页由具体业务模块负责，不在前端传库名、连接串或 SQL，不对 MES 表运行迁移。
3. **已确认：站点查询第一版数据源对照。** 站点查询规则暂定为：`MesE` 对应 SBU1、SBU8；`MesF` 对应 SBU2、SBU3；`MesEB` 对应 SBU4；VNK 对应 SBU7，但当前阶段不接入 VNK。这个对照只用于站点查询的策略解析，不能推导其他业务的数据源，也不能代替记录级 SBU 过滤。
4. **下一步：核实站点数据归属。** 取得 E、F、EB 库的站点表、机种表及中间表定义，明确站点到机种的关联、机种上的 SBU 字段、历史数据归属以及三库 SQL 差异。旧 `zxadmin/ZXAdmin.Domin.Service/Service/BaseData/TerminalService.cs` 可作为站点字段参考：它查询 `SAJET.SYS_TERMINAL`、`SYS_PDLINE`、`SYS_PROCESS`，但没有展示站点到机种或 SBU 的关联，不能直接当作范围过滤 SQL。必须用真实库结构和样本数据验证同库 SBU1/SBU8、SBU2/SBU3 是否能可靠分开；无法判定归属的记录不得默认返回。
5. **实现站点查询试点。** 在现有后端独立组织 MES 业务代码，建立一个普通站点查询菜单和权限；业务内部按“站点查询 + 已验证 SBU Code”选择 E/F/EB 查询实现，两种以上实现返回同一 DTO。列表、详情及导出使用相同范围规则，缺少该 SBU 的策略时明确拒绝，不回退到整库。Controller 复用当前 JWT、功能 Policy 和 `[RequireSbu]` 校验。
5. **另做跨 SBU 查询。** 只有确有需求时，建立独立菜单、权限和接口；它不依赖用户的逐个 SBU 关联，也不把“全量”能力扩展到其他功能。上线前明确跨库分页、去重、排序和部分失败规则。

站点接口验收至少覆盖：无登录、无功能权限、缺失/伪造/无关联/停用的 SBU、同库 SBU2/3 互不越界、无可用策略、分页边界和 MES 故障。任何一项未确认时不对外开放站点数据。

## 工作线 B：低代码平台

另一位开发者可立即在独立任务中推进低代码方案和本系统低风险 CRUD 试点。优先维护自己的模块与文档；不要修改 Identity 的 SBU 关系、`[RequireSbu]`、前端 `sbuScoped` 契约或站点查询策略。如需调整共同契约，先在本交接文档说明变更，再同步双方实现。

低代码的分层模型、复用权限与菜单、全局 / SBU 数据范围及第一期边界见[低代码平台方案讨论](low-code-design.md)。

1. **明确试点交付。** 选择一个本系统自己的低风险 CRUD 功能，让开发人员通过可视化配置完成字段、表单、列表、校验、菜单与操作权限，再生成或发布可运行的应用。先评估现有开源方案与项目 Vue 3 / .NET 10 / 动态菜单 / 权限模型的适配成本；若沿用当前规划的代码生成方式，生成物仍要进入代码审查、测试和部署。记录哪些步骤仍需人工写代码，以判断是否达到“开发直接使用低代码”的目标。
2. **建立受控数据集目录。** 每个数据集明确所有者、来源、允许字段、过滤规则、读写能力、功能权限代码及是否需要 SBU。编辑器只能引用已发布的数据集，不允许配置数据库密码、直连任意 MES 表或提交任意 SQL。外部 MES 数据集由工作线 A 的业务 API 提供，不能由低代码端直接绕开站点查询规则。
3. **复用授权模型。** 应用/页面/操作纳入现有角色权限和动态菜单；数据集读写在服务端校验权限。SBU 数据集由服务端读取已验证的当前 SBU，查询和写入都按归属限制。全局数据集显式声明无需 SBU。低代码配置者不能通过配置扩大自己或最终用户的数据范围；跨全部 SBU 的数据集须有独立权限。
4. **试点验收。** 普通用户只能看获授权菜单和数据；没有权限的直接 API 调用被拒绝；切换 SBU 后页面和查询结果更新，旧结果不会混入；无 SBU 的用户仍可使用全局数据集；修改配置不会绕过字段白名单、SBU 范围或操作权限。记录方案、配置模型、生成/发布流程和维护成本，再决定扩大到 MES 数据集或运行时页面设计。

低代码工作线可以先做第 1、2 项和本系统 CRUD 试点；接入 MES 的时间点以工作线 A 的站点 API 与数据范围验收为准。

## 当前缺少的业务资料

站点查询实际开发需要：E/F/EB 库可用的连接方式、三库站点和机种相关表结构、站点到机种的关联字段、机种的 SBU 字段及取值、三库查询差异、样本数据和期望返回字段。VNK 暂不需要提供连接或表结构。连接凭据只通过环境密钥配置提供，不写进文档。没有这些资料时可完善契约与安全边界，但不能编造站点 SQL 或开放无范围过滤的结果。
