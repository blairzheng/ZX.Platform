# 低代码平台方案讨论

[两条工作线交接](sbu-mes-lowcode-handoff.md) · [外部 Oracle 数据源](external-oracle-data-sources.md) · [角色与权限](authorization.md)

更新于 2026-10-29。本页记录已讨论确认的设计边界，供后续试点和选型使用；当前没有低代码编辑器、运行时或生成器。具体技术选型和接口契约仍待试点确定。

## 目标与基本模型

同一套低代码配置与页面能力应兼容本系统业务和外部系统数据。区分以下三层，不能把数据库连接、业务数据集和页面视为一对一关系：

| 层次 | 职责 |
| --- | --- |
| 数据源 | 本系统业务服务、外部 API、外部数据库等实际数据来源；连接别名和凭据只由服务端管理。 |
| 业务数据集 | 对页面发布受控的字段、筛选、排序、分页、操作及返回契约；由业务服务实现查询或写入，并声明每项操作的功能权限和数据范围。一次操作可以在服务端使用多张表或多个数据源。 |
| 页面 | 配置列表、表单、筛选项和操作入口；一个页面可以引用多个已发布的业务数据集，不直接决定连接、SQL 或数据范围。 |

本系统数据集由本系统业务服务实现；外部数据集由对应业务适配代码实现。低代码编辑器只能引用已发布的数据集，不能配置数据库密码、任意 SQL，也不能直接对现有 Identity 表生成通用增删改。外部写入必须遵守对应业务服务的规则，不能因为页面支持表单就默认开放写入。

## 权限、菜单与数据范围

复用现有账号、角色、功能权限、权限缓存和菜单目录。低代码需要区分配置编辑与发布权限、页面查看权限，以及数据集各项操作的权限。菜单和按钮控制展示；服务端对每次数据集操作独立授权，直接调用 API 也不能绕过检查。页面引用一个数据集不自动授予该数据集的操作权限；配置者也不能通过发布页面扩大最终用户的权限。

数据范围由业务数据集的操作显式声明，不把 SBU 作为所有低代码功能的默认条件：

| 范围 | 服务端执行规则 |
| --- | --- |
| 全局 | 检查相应功能和操作权限；不要求用户关联或选择 SBU，不发送 `X-SBU-ID`。全局仅表示不按 SBU 隔离，不表示所有登录用户都可访问。 |
| 按 SBU | 检查功能和操作权限，再验证所选 SBU 属于当前用户且已启用；列表、详情、导出和写入都要按业务记录归属限制。 |

同一页面可同时使用全局和按 SBU 的数据集，各请求按自身范围执行。前端按 SBU 的请求使用现有 `sbuScoped: true`；后端复用 `[RequireSbu]` 和 `CurrentSbuContext` 验证选择。该校验只证明用户可访问所选 SBU，不能代替业务查询和写入时的记录归属检查。无 SBU 的用户仍可使用获授权的全局功能。跨全部 SBU 的查询若有明确需求，应另设功能权限和接口，不能通过普通数据集配置开启。

现有权限目录由 `IdentityPermissions` 静态常量同步，`MenuService` 和前端动态路由只接受固定页面组件。低代码接入时应扩展权限注册与菜单组件白名单，增加受控的低代码页面入口；运行页面只加载已发布的配置，不能按配置加载任意前端模块。试点若随代码部署，可先注册固定权限；若要求发布配置后立即新增权限和页面，则需要进一步设计动态权限目录、审核发布和缓存失效。两种发布方式尚未选定。

## 站点查询对模型的要求

站点页面可能同时使用站点列表、产线或工序选项等多个业务数据集。站点列表本身也可能关联多张 MES 表，并由后端按“站点查询 + 已验证 SBU”选择 E/F 库的查询实现；页面不传库名或 SQL。SBU2、SBU3 即使共用 F 库，也必须按记录归属分别过滤。E 库对应 SBU1、F 库对应 SBU2/3 目前只是待核实示例，不应写成所有业务通用的 SBU 到数据源映射。

站点到机种的关联链、机种上的 SBU 字段和历史记录归属仍需用真实库结构与样本数据确认。确认前不能发布站点数据集或返回无法判定归属的记录。站点业务接口及其范围规则由 SBU / MES 工作线完成；低代码平台随后将这些受控业务能力作为数据集接入，不重新实现一套站点选库或过滤逻辑。详见[实施交接](sbu-mes-lowcode-handoff.md#工作线-a-sbu-与-mes-外部数据集)。

## 第一期与待定项

第一期先用本系统一个独立、低风险的 CRUD 功能验证字段、表单、列表、校验、菜单、操作权限、数据范围和发布流程；再用经过业务范围验证的外部只读数据集验证外部接入。页面模型从一开始允许引用多个数据集。跨来源关联、同步和一次写入多个系统的一致性后续再设计，不作为第一期启动前提；即使第一期页面使用多个数据集，也不承诺跨数据集事务。

试点前仍需明确具体 CRUD 业务、数据集定义与审核流程、选用开源方案还是自行实现，以及生成代码后部署还是运行时读取已发布配置。若采用代码生成，生成物仍进入正常代码审查、测试和部署。试点应记录仍需人工编写的内容和维护成本，再决定是否扩展运行时页面设计能力。
