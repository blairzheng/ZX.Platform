# NPI：GoFlow 阶段资料看板需求

整理日期：2026-11-10。状态：待开发，用于需求交接。业务范围已按本次讨论确认；本文的页面、接口和查询尚未实现，技术接入仍需核对实际数据库及线上详情路径。

## 1. 业务目标与本期范围

MOM 的 NPI 模块需要按项目、项目阶段，汇总多个业务系统的信息。第一期接入 GoFlow，承载 NPI 总览中的“Project 文件状况”：用户在 MOM 查看各阶段已有的状态数量及资料明细，查看具体资料、上传及审核时进入 GoFlow 原页面。

已确认需求：

- 直接使用 GoFlow 源项目及其真实阶段，展示各阶段的源状态数量，并提供资料项明细。
- MOM 后端直接读取现有 `MesC` 数据源中 `PROJECTRMS` Schema 的 GoFlow 业务表，向 MOM 前端提供查询结果。
- 数量及状态解释沿用 GoFlow 当前统计逻辑；MOM 负责查询、汇总和展示，不新建必交/选交清单、不重定义偏差或完成规则、不计算合并完成率。
- 首期不建立跨系统机种与项目映射，不合并同名或同机种的多个源项目。后续融合其他系统时再按独立需求增加映射。
- 暂不按 SBU 隔离；入口及查询接口受 MOM 功能权限控制，具体范围见第 5 节。
- 仅要求定位具体资料项详情，沿用已接入的 MOM SSO，在新标签页打开，保留当前 MOM 页面。

本期只做 GoFlow 资料查询与跳转。材料、治工具、OK2B/OK2S/LQ、良率、LL 等系统留待后续分别接入；资料上传、删除、审批和项目维护继续使用 GoFlow，本期不改动 GoFlow 的业务规则。

参考图中的 P1(PP1)、P2、EVT、CRB、DVT 用于说明展示方式。GoFlow 阶段可自由维护，第一版展示其真实阶段名称和顺序，不将这些名称写死。`2F/13T`、MCO/SCH 暂不作为已定义字段，需另行确认业务含义。

## 2. 用户流程与页面

建议页面名称为“NPI 项目总览”，第一期展示 GoFlow 区域。菜单路径和组件标识由实施人员按 MOM 现有动态菜单约定确定并交付，菜单与角色授权由负责人配置。

基本流程：选择项目分类（有需要时）→ 搜索并选择 GoFlow 项目 → 查看各阶段状态数量 → 点击阶段或“查看明细”打开 MOM 资料项列表 → 点击某个资料项进入 GoFlow 对应详情。

页面要求：

1. 项目选项显示名称及分类，使用源项目 ID 区分；同名项目不能仅按名称合并。当前 GoFlow 未发现独立标准机种编码，第一期不另建 MOM 项目主档或映射维护功能。
2. 阶段区展示真实名称、起止时间（源数据存在时）和状态数量；阶段多时允许横向浏览。无阶段、无配置任务分别显示对应空状态。
3. 不把阶段列表第一个阶段标为“当前阶段”，也不凭顺序、开始时间或资料完成比例推断项目正在进行的阶段；这需要独立业务规则。
4. 各阶段摘要按第 4 节展示 GoFlow 现有统计合计及各状态数量。摘要使用“状态统计”表述，不能将其标成文件总数、应交数或完成率。
5. 资料项列表沿用源任务矩阵的资料条目，展示任务路径、资料项名称、任务内步骤、类型、有效附件数、提交/审核状态及查看入口；一个资料项存在多个审核节点时保留其对应关系。截止时间、责任角色仅在能够从源数据准确取得时展示。
6. 资料项列表支持按名称、任务及源状态服务端筛选和分页。阶段摘要保持源阶段完整统计，列表筛选和当前分页不改变摘要。支持手动刷新；切换项目后清除不适用的阶段和筛选，旧请求结果不能覆盖新项目。
7. 无数据、无权限、数据源失败分别展示。查询失败不能展示为“全部为 0”或“全部完成”；刷新失败保留旧结果时必须提示结果未刷新。
8. 复用 MOM 现有页面组件、分页、请求层和中英文词条，适配浅色与深色主题。接口、表名、连接别名等实现信息不进入业务页面。

## 3. 数据来源及关系

`MesC` 是 MOM 服务端已有的外部 Oracle 连接别名；`PROJECTRMS` 是本次指定的 GoFlow 表所属 Schema。查询通过现有 `IExternalOracleConnectionFactory.OpenAsync("MesC", ...)` 接入。连接凭据继续保存在本地 User Secrets 和部署变量中，不增加前端数据库配置。

根据源码确认的关系：

```text
项目分类
└─ 顶层项目 / 机种：pms_project，ParentId = "0"
   └─ 项目阶段：pms_project，ParentId = 顶层项目 ID
      └─ 任务树：pms_work，ProjectId = 项目阶段 ID
         └─ 任务矩阵
            ├─ 行 / 任务内步骤：pms_workstage
            └─ 列 / 资料项定义：pms_workdetail + pms_workdetailapprove
               └─ 行 × 列的实例
                  ├─ 提交 / 流程：pms_workdapproveform
                  ├─ 审核记录：pms_workapproveaudit
                  └─ 附件：pms_file
```

以上是源码映射名称，实际 Oracle 表名、字段大小写、权限和数据分布须在开发时核实，不能据此假定已完成连库验证。

特别注意：GoFlow 的 `projectId` 在任务查询中通常是“项目阶段 ID”；`stageId` 是任务矩阵行 ID。MOM 对外契约建议用 `projectId`、`phaseId`、`taskStepId` 明确区分，仓储负责映射。

## 4. 各阶段数量与源状态

### 4.1 沿用 GoFlow 原始状态统计

各项目阶段按 GoFlow `WorkService.TableCount` / `ForeachWorkCount` 的当前逻辑汇总，保留源字段，逐阶段与源系统对账。本期不另建资料项分母或完成算法。

| 源字段 | 展示含义 | 源统计规则摘要 |
| --- | --- | --- |
| `All` | 状态统计合计 | 以下六类数量相加 |
| `Available` | 待处理 | 已有结果为 Available 的审核节点，加按源审核类型及角色配置推算的待处理节点 |
| `Rejected` | 驳回 | 审核结果为 Rejected 的节点数 |
| `Deviated` | 偏差 | 审核结果为 Deviated 的节点数 |
| `Approved` | 通过 | 审核结果为 Approved 的节点数 |
| `NeedsData` | 待提供资料 | 没有提交表单且配置了审核的单元格数 |
| `BlankCells` | 无审核单元格 | 源统计归入 BlankCells 的单元格数；包含已有表单但无审核配置的情况 |

上述数量混合了审核节点和单元格口径。同一资料项的多个审核角色或层级可以贡献多个计数；`All` 不是文件数或去重资料项数，`Approved` 不是已完成文件数，`BlankCells` 也不是未上传文件数。前端使用业务标签，源字段供开发契约及对账使用。

阶段统计从根任务按源逻辑递归处理子任务，使用对应阶段的 `pms_project.Id`。主任务级 SOP 附件不在这套 `All` 内，不能为凑齐文件总数擅自加入。源逻辑不按资料名称、状态等列表筛选计算摘要，MOM 也不将这些筛选套入阶段统计。

### 4.2 资料项明细

- 以源阶段、任务、任务内步骤及资料列标识定位资料项；查询从源配置出发，尚未提交的条目也可展示。
- `ApproveType`、审核配置、表单及审核记录按源关系解释。配置项或子任务入口没有资料详情目标时，不伪造文件入口；子任务中的实际资料仍可查看。
- 附件数量独立取匹配资料项的有效记录（`Enabled=1`），按阶段、任务、矩阵行、资料列、附件类型及适用表单正确关联，避免重复或串用。附件记录数不替代阶段统计。
- 只读展示源表单及审核状态，不新增必交/选交/不适用判断，不为主任务级 SOP 补应交清单，不推导“未上传 = All - 已上传”。

源 `FormStatus` 有进行中、已完成、驳回；`AuditResult` 有 Available、Rejected、Deviated、Approved、Needs Data，也存在 `-1`。这些维度分开展示，不把无需审核已完成改成审核通过，不把偏差并入通过。未知或空状态保留可解释的展示；本期不要求一个合并完成率，也不显示默认 100%。

## 5. 权限与查询边界

新增 NPI 查询权限建议使用 `npi.goflow.read`（拟定，待实施），后端接口独立校验；不能仅依靠菜单隐藏。MOM SSO 使用现有 `integration.goflow.open`，两项权限用途不同，不能互相代替。

首期数据范围按本次讨论确定：

- 只有取得 NPI 查询权限的 MOM 账号可查询本次接入数据源中的 GoFlow 源项目、阶段摘要及资料项明细。不能向所有已登录账号默认开放，也不能只隐藏菜单。
- 暂不按 SBU 过滤，切换 MOM 当前 SBU 不改变本模块查询结果。不把 GoFlow 项目分类当作 SBU，不按名称猜测映射，不接收客户端自报 SBU 作为数据授权依据。
- 首期不复制 GoFlow 项目团队、任务角色等过滤机制；MOM 查询按上述独立功能权限开放接入项目范围。因此 MOM 可见范围可能大于该账号在 GoFlow 的范围，进入资料项详情后仍由 GoFlow 自身认证授权，不能绕过其校验。
- NPI 存在阶段保密需求，但目前没有确认可靠的源项目到 MOM SBU 映射，首期尚未实现 SBU 数据隔离。有查询权限的账号可看到跨 SBU 的接入项目；授权配置及交付说明必须明确这一现状。后续确认映射后另行增加服务端隔离，并同步摘要、列表、明细和缓存范围。
- 项目与阶段、任务、资料项的归属关系由服务端校验，修改 ID 不能串用其他项目的条目。验收覆盖有查询权限和无查询权限的账号。

第一期不要求向 AI 开放这些新查询。需要开放时，在统计口径与权限确定后按现有 `[AiQuery]` 约定处理，不额外赋予 AI 数据权限。

## 6. GoFlow 明细与 SSO 跳转

1. 在新标签页打开固定、获准的 GoFlow 站点，使用 `sso=mom` 触发现有免登录流程，保留其他业务参数。沿用现有 OA 身份及 GoFlow 自身授权，不另建一套登录逻辑。
2. 只要求定位具体资料项。现有详情页支持 URL 参数：`projectId`（源项目阶段 ID）、`workId`、`stageId`（矩阵行 ID）、`workDetailId`、`fileType`，名称和面包屑仅作为展示信息并正确编码。动态菜单中实际路由须核实，源码常见路径为 `/pms/workBoardTask`。
3. 现有详情页只有同时取得 `projectId` 与 `workDetailId` 才使用 URL 参数，否则可能依赖旧的浏览器本地状态。验收必须使用全新标签页/清空业务状态，不能依赖用户之前点过 GoFlow。
4. 点击阶段只在 MOM 查看该阶段资料项列表，本期不要求跳到 GoFlow 工作台并预选阶段，不增加工作台的参数初始化改造。
5. 非 OA 用户、无 SSO 权限或 SSO 未启用时，入口显示明确说明；如保留普通 GoFlow 登录入口，应明确标注并保留安全的业务目标，由 GoFlow 自行认证授权。
6. 不把 Token、服务密钥、数据库连接信息或可编辑的任意跳转地址放入业务链接。

## 7. 建议接口与实施约束

以下仅为开发契约建议，尚未实现；开发时可按项目约定调整命名并同步最终文档。Identity 直连以 `/api/NpiGoFlow` 为前缀，浏览器沿用 Gateway 的 `/api/identity/api/...` 路径。

| 拟定接口 | 输入 | 返回 |
| --- | --- | --- |
| `GET projects` | 分类、搜索词、`page`、`pageSize` | 接入范围内的源项目选项 `{list,total}`，含 ID、名称、分类 |
| `GET phases` | 必填 `projectId` | 该项目真实阶段及各阶段源状态数量、统计范围和查询时间 |
| `GET items` | 必填 `projectId`、`phaseId`，可选名称及源状态筛选、分页 | 资料项 `{list,total}`，含源标识、业务字段、附件/表单/审核状态和可用详情跳转目标 |

实施要求：

- 按现有 Controller → Application Service → Repository 分层，Oracle 读取放 Infrastructure；Controller 不直接连接数据库。
- 源 Schema 和允许的表固定在服务端；条件值参数化，限制分页大小，排序包含稳定次级键。不能接受客户端任意 Schema、SQL 或数据源别名。
- 每个查询设超时并传递取消令牌；尽量批量聚合，避免按每个单元格逐次查库，避免一次返回全部附件正文或文件内容。
- 阶段统计在后端按源阶段完整范围计算，列表分页及筛选独立处理，不用当前页条目数计算摘要。数量逐项与 GoFlow 源统计对账，不自行改写源业务判断；多表读取须保证一致口径。
- 优先沿用现有 `MesC` 配置与部署映射，只读接入不创建/修改 GoFlow 表，不为这些外部表生成 MOM EF Migration。
- 返回 `ApiResponse<T>`；成功为业务码 0。超时/数据源不可用按现有异常机制处理，不返回成功的空结果；日志不记录凭据、连接字符串或资料正文。
- 初版支持进入页面及手动刷新时查询。若增加短时缓存，缓存键必须包含数据授权范围和查询条件，页面显示数据时间，不能跨用户泄露结果。

## 8. 验收清单

1. 项目及其阶段名称、顺序、起止时间与 GoFlow 一致；同名源项目独立展示，不新增机种映射或推断“当前阶段”。
2. 选取有多角色审核、子任务、尚无表单及无需审核单元格的阶段，将七个统计字段与 GoFlow 同阶段完整统计逐项对账；`All` 等于六类相加。
3. 多审核节点仍按源规则计数，页面不会将其误标为去重资料数或文件数；`BlankCells` 不显示为未上传，主任务 SOP 附件不擅自加入 `All`。
4. 表单状态、审核状态、偏差及无需审核情况与源明细一致；未知状态不被显示为通过，不增加完成率或必交清单。
5. 资料列表按源配置及关联数据展示；无提交条目可见，附件有效性及归属正确。同名任务、多层子任务、不同项目和阶段的数据互不串用，列表筛选分页不改变阶段摘要。
6. 无 NPI 查询权限时，直接调用项目、摘要和明细接口同样被拒绝；有权限账号按首期接入范围查看数据，切换 SBU 不产生虚假的隔离效果。交付说明明确暂未按 SBU 或 GoFlow 团队隔离。
7. 点击阶段在 MOM 打开列表，点击资料项才在新标签页打开 GoFlow；在没有旧业务缓存的标签页完成 SSO 并定位正确条目，GoFlow 自身权限仍生效。
8. 非 OA、无 SSO 权限、目标已删除及查询失败等情况有明确反馈；中英文/深色主题、刷新、快速切换项目和空状态符合页面要求。大项目的查询时延与执行计划在目标环境评估并记录。
9. 前后端交付最终 API 契约、源统计映射、菜单/组件标识、权限及首期数据范围、详情路由、配置需求和实际验收结果；业务文档同步为最终实现。
