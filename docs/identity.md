# Identity 业务语义

[文档导航](README.md) · [接口契约](api.md) · [API 响应与错误](http.md)

这里记录用户与SBU用例的行为规则、状态变化和当前能力边界。路由、HTTP 方法、请求字段、分页参数和错误负载见[接口契约](api.md)；所有路径经 Gateway 调用时加 `/api/identity` 前缀。

## 状态与SBU关系

- 创建用户 / SBU时默认启用；软删除同时禁用，恢复时重新启用。
- 普通详情及状态操作查不到软删除对象，返回 `404 / 600002`；恢复接口通过包含删除数据的查询取得对象。
- 对未删除对象调用恢复返回 `409 / 600003`。实体也保护“删除后不能直接启用”的规则，但普通启用 HTTP 接口会先受查询过滤器影响。
- `updateUserSbus` 提交的是目标完整关系集合：保留共有关系、新增缺失关系、物理删除不再需要的关系，最后一次保存。
- 用户可以不关联 SBU；提交空数组会清空全部关系。只有全局功能的账号不必绑定 SBU。
- 删除 / 停用用户或SBU不会自动删除关系。`Auth/me.sbus` 只返回关联且当前启用的 SBU；默认SBU设置、业务接口的访问校验和跨SBU数据隔离尚未实现。
- 禁用、单个 / 批量软删除用户及自助改密码会撤销用户会话；启用和恢复不会恢复已撤销的会话。管理员强制下线只撤销会话，不禁用账号；不再提供管理员重置密码。Redis 故障及并发登录的容忍边界见[登录与会话](authentication.md)。SBU启停用不撤销用户会话，SBU数据授权仍待实现。

## 账号类型与开通审批

用户表同时承载本地账号和 OA 账号，用 `AuthType` 区分，两类账号不合并、不互相切换认证方式。

- `LOCAL` 账号必须保存本地密码哈希，只能用 `Auth/login` 登录，密码由 ZX 维护。
- `LDAP` 账号不保存密码哈希（数据库以 CHECK 约束保证），只能用 `Auth/ldapLogin` 由目录验证密码；角色、权限、菜单和 SBU 仍完全由 ZX 管理，不从目录继承。
- `LDAP` 账号的 `ACCOUNT` / `NORMALIZED_ACCOUNT` 固定取工号，目录登录名（如 `sAMAccountName`）只用于目录认证。首次登录建档和预开通两条路径一致，冲突检查也按工号执行，所以“本地账号已占用该工号”一定返回冲突，不会因为目录登录名不同而漏检。
- 账号是否可用由 `ApprovalStatus` 和 `IsEnabled` 共同决定：Pending / Approved OA 账号在启用且未删除、未锁定时均能登录；Pending 没有业务授权资格，角色/菜单/权限/SBU 强制为空。Rejected 不能启用，数据库 CHECK 保证已拒绝 OA 账号禁用。
- 存量用户迁移后为 `LOCAL` / `Approved`，Id、密码哈希、角色和 SBU 都不改变。

开通路径只有两条，结果都以同一个 UserId 继续使用：

1. **管理员预开通**：先 `ldapLookup` 按工号只读核对姓名、部门和目录状态，再 `addLdap`。`openImmediately=true` 一次完成创建、审批、角色和 SBU 分配；`openImmediately=false` 只建待审批记录。
2. **首次登录申请**：未预开通的员工在 `ldapLogin` 中通过目录认证后，服务端自动生成 `Pending / Enabled` 账号和 UserId，签发受限会话进入应用中心。审批前再次登录沿用同一账号及单会话接管规则，不会重复建档。

审批通过时角色和 SBU 在同一事务中写入，`SecurityVersion` 做乐观并发校验，两人同时审批只有一人成功，另一人收到 `409` 而不是静默覆盖。拒绝后账号保持 `Rejected`，该工号再次登录返回拒绝（403），不会被自动重建；`Rejected` 可以在之后重新审核通过。

存量 Pending / Disabled 不会被此次迁移批量启用；需管理员显式启用。Pending 被禁用后，批准只改变业务资格和授权，仍保留禁用；Rejected 的显式重新审核通过会恢复启用。

审批不是万能的启用开关：`ApproveLdap` 只接受 `Pending` 和 `Rejected`，任何 `Approved` 状态都直接拒绝。已通过后被禁用的账号必须走 `setUserEnable`，这样“审批 + 角色 + SBU”三项权限不能代替 `identity.user.status`，也不能借审批顺手改写现任管理员的角色。角色替换复用角色接口的完整保护：目标原本是管理员或将被设为管理员时，只有管理员能执行，且不能移除自己的管理员身份。

每次预开通、通过、拒绝和重新审核都追加一条 `UserApprovalAudit`，记录操作人、动作、前后状态、原因、角色与 SBU 快照和 TraceId。用户表上的三个审核字段只表示最近一次审核，重新审核会覆盖，因此历史只能查审计表。角色与 SBU 快照按 CLOB 保存（`20261102150741_WidenApprovalAuditSnapshot`），数量只受业务权限约束，不会因为审计字段长度让一次合法审批整笔失败，也不会截断已有审计数据。

冲突一律拒绝而不是自动修正：本地已存在同工号账号时不合并、不改写为 OA；同一目录唯一标识已绑定其他账号时不迁移授权；目录禁用、工号不存在、结果不唯一或缺少唯一标识时不开通。目录故障按依赖不可用处理，不猜测账号是否存在。

## 批量软删除

请求体形状、状态码和提示键见[接口契约](api.md#批量软删除)。数据侧行为：

- 软删除同时禁用用户，保留SBU关系，审计时间由现有拦截器填写。
- 只处理查到的未删除用户，不要求所有 ID 都命中：重复 ID 不会重复处理，不存在、已删除或 `Guid.Empty` 的 ID 被跳过；即使所有 ID 均未查到，也返回成功。
- 不返回实际删除数量，调用方不能显示推测的删除数量。

## 接入边界

用户、SBU、登录及角色权限已完成前后端代码接入，真实数据库与浏览器联调待验收。管理接口要求 Bearer 及对应功能权限；角色新增、授权和用户角色分配已提供，见[角色与权限](authorization.md)。动态菜单与树形角色授权已接入，见[菜单接口](api.md#菜单接口)。批量启停用、报表下载等接口尚未提供。批量入口按实际后端契约一次提交 ID 数组，不能通过循环调用单条接口来拼成批量操作。

修改用户名称和关系等多个独立 HTTP 请求没有一个跨请求事务，发生部分失败时需要重新查询确认已保存的状态。响应、重试和取消的语义见[HTTP 专题](http.md)。
