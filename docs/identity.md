# Identity 业务语义

[文档导航](README.md) · [接口契约](api.md) · [API 响应与错误](http.md)

这里记录用户与厂区用例的行为规则、状态变化和当前能力边界。路由、HTTP 方法、请求字段、分页参数和错误负载见[接口契约](api.md)；所有路径经 Gateway 调用时加 `/api/identity` 前缀。

## 状态与厂区关系

- 创建用户 / 厂区时默认启用；软删除同时禁用，恢复时重新启用。
- 普通详情及状态操作查不到软删除对象，返回 `404 / 600002`；恢复接口通过包含删除数据的查询取得对象。
- 对未删除对象调用恢复返回 `409 / 600003`。实体也保护“删除后不能直接启用”的规则，但普通启用 HTTP 接口会先受查询过滤器影响。
- `updateUserFactories` 提交的是目标完整关系集合：保留共有关系、新增缺失关系、物理删除不再需要的关系，最后一次保存。
- 当前 DTO 至少要求 1 个厂区，不能通过空数组清空全部关系。
- 删除 / 停用用户或厂区不会自动删除关系。默认厂区设置、真实授权校验和跨厂区数据隔离尚未实现。

## 批量软删除

请求体形状、状态码和提示键见[接口契约](api.md#批量软删除)。数据侧行为：

- 软删除同时禁用用户，保留厂区关系，审计时间由现有拦截器填写。
- 只处理查到的未删除用户，不要求所有 ID 都命中：重复 ID 不会重复处理，不存在、已删除或 `Guid.Empty` 的 ID 被跳过；即使所有 ID 均未查到，也返回成功。
- 不返回实际删除数量，调用方不能显示推测的删除数量。

## 接入边界

用户页面的新增、查询、修改、单个启停用、单个删除和批量删除已接入这些契约。批量启停用、登录、当前用户、角色、菜单、报表下载等接口尚未提供。批量入口按实际后端契约一次提交 ID 数组，不能通过循环调用单条接口来拼成批量操作。

修改用户名称和关系等多个独立 HTTP 请求没有一个跨请求事务，发生部分失败时需要重新查询确认已保存的状态。响应、重试和取消的语义见[HTTP 专题](http.md)。
