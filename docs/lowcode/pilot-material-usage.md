# 落地场景：MES 机种用料盘点

更新于 2026-10-30。这是低代码平台的**第一个真实业务**，也是 M1 的验收对象。

选它的理由：它一次压到平台的六个能力——外部只读数据集、主从、行内编辑、导出、权限、SBU 范围。任何一项没做好，这个页面就用不了。

## 1. 业务描述

产线要盘一个机种用了哪些料、各用多少。数据分两部分：

- **来自 MES 的主数据**：机种、线体、站点、料号 —— 只读，不允许在低代码里改
- **平台自己维护的盘点数据**：盘点单 + 用料明细 —— 可增删改

日常操作是：新建一张盘点单 → 选机种/线体/站点 → 逐条加料号和用量 → 导出发人。

使用者是开发 / 实施顾问，不是产线操作工。

## 2. 数据模型

**主表 `mes.stocktake`（盘点单）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `autonumber` | 单号，前缀 `PD`，唯一 |
| `model_code` | `relation` → `mes_model` | 机种，必填 |
| `line_code` | `relation` → `mes_line` | 线体，必填 |
| `station_code` | `relation` → `mes_station` | 站点，可空 |
| `stocktake_date` | `date` | 盘点日期，必填，默认 `$now` |
| `status` | `select` | `draft` / `submitted`，默认 `draft` |
| `remark` | `longtext` | 备注 |

唯一约束：`code`。索引：`model_code`、`line_code`、`stocktake_date`。

**子表 `mes.stocktake_line`（用料明细）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `stocktake_id` | `relation` → `mes_stocktake` | 所属盘点单，必填，建索引 |
| `material_code` | `relation` → `mes_material` | 料号，必填 |
| `quantity` | `number(18,4)` | 用量，必填 |
| `unit` | `select` | 单位（PCS / M / KG / SET） |
| `remark` | `text` | 备注 |

唯一约束：`(stocktakeId, materialCode)` —— 同一张单里料号不能重复。

> **第一期用松主从**：明细是独立实体，靠 `stocktake_id` 关联。页面上从盘点单点进明细列表，不在一个表单里嵌子表格。紧主从（嵌入式）放第二期。

## 3. 外部只读数据集

四个数据集，全部只读，全部按 SBU 过滤。

| 数据集 | 用途 | 取数字段 |
| --- | --- | --- |
| `mes_model` | 机种下拉 | `code`、`name` |
| `mes_line` | 线体下拉 | `code`、`name` |
| `mes_station` | 站点下拉 | `code`、`name`、`line_code` |
| `mes_material` | 料号下拉 | `code`、`name`、`spec`、`unit` |

约束：

- **只生成 `SELECT`**，不接受手写 SQL
- 行数上限 5000，超时 10 秒，必须带过滤条件
- 连接用只读账号，凭据走环境变量，不进元数据
- SBU 过滤由数据集声明（绑定变量 `:sbuId`），页面配置无权更改

> **待确认**：这四类数据在 MES 里对应的表或视图名、是否有 `SBU_ID` 列、字段类型。给了就能把数据集配置写死。

## 4. 页面与交互

**盘点单列表**（`/mes/stocktake`）

- 列：单号、机种、线体、站点、盘点日期、状态、明细数、更新时间
- 筛选：机种、线体、站点、日期区间、状态
- 操作：新增、编辑、删除、**导出 Excel**、进入明细

**盘点单表单**（弹窗）

- 字段按 §2 主表定义渲染，`code` 只读（自动生成）

**明细列表**（点单号进入，`/mes/stocktake/{id}/lines`）

- 列：料号、名称、规格、用量、单位、备注
- **行内编辑**：用量直接在表格里改，不弹窗
- 操作：新增料号（弹窗，料号下拉来自 `mes_material`）、删除、批量删除

## 5. 权限

| 权限码 | 说明 |
| --- | --- |
| `mes.stocktake.read` | 查看盘点单与明细 |
| `mes.stocktake.create` | 新建盘点单、新增明细 |
| `mes.stocktake.update` | 修改单头、行内改用量 |
| `mes.stocktake.delete` | 删除盘点单与明细 |
| `mes.stocktake.export` | 导出 |

**明细不单独设权限码**，继承主表。否则一张单要配十个码，实施顾问会疯。

## 6. 导出

服务端导出，MiniExcel，按当前筛选条件全量导出。

- 一个 sheet：明细展开，每行带单号/机种/线体/站点/日期
- 上限 50000 行，超出报错并提示缩小范围
- 走 `mes.stocktake.export` 权限 + SBU 过滤
- 记录审计：谁、什么时候、导出了多少行

## 7. 验收用例

**功能**

- [ ] 新建盘点单 → 列表可见 → 编辑 → 删除 → 列表不可见
- [ ] 单号自动生成，前缀 `PD`，重复新建不撞号
- [ ] 同一张单加重复料号 → 被拒
- [ ] 行内改用量 → 刷新后仍生效
- [ ] 明细为空时导出的表头正确（不报错）

**外部数据集**

- [ ] 机种下拉能取到 MES 数据
- [ ] 料号下拉能按关键字前缀搜索
- [ ] 数据集返回超过 5000 行 → 明确报错，不是静默截断
- [ ] 数据集 SQL 里能看到 `:sbuId` 绑定变量

**权限**

- [ ] 无 `read` → 列表 403
- [ ] 有 `read` 无 `export` → 导出按钮不可见，直接调 API 也 403
- [ ] 直接调 API 绕过前端按钮 → 同样被拒

**SBU**

- [ ] 无 SBU 访问 → 403，不回退全量
- [ ] 伪造 `X-SBU-ID` → 403
- [ ] A 厂区的单子，B 厂区用户按 ID 直接取 → 404
- [ ] 新增时请求体里带 `SBU_ID` → 被忽略，按上下文写入

**导出**

- [ ] 导出内容与列表筛选一致
- [ ] 导出只含本 SBU 数据
- [ ] 超过 50000 行 → 报错
